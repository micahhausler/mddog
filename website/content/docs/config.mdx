## Config file

To change a default setting, create a config file `~/.config/mddog/config.toml`. (If `XDG_CONFIG_HOME` is set, use `$XDG_CONFIG_HOME/mddog/config.toml` instead.)

This is a config with every key at its default value:

```toml title="~/.config/mddog/config.toml"
theme = "light:github-light,dark:github-dark"
copy_on_select = false
callouts = "github"
open_command = ["open"] # ["xdg-open"] on Linux
max_width = 100

[file_list]
extensions = ["md", "markdown"]

[file_list.preview]
position = "right"
size = "50%"
narrow_columns = 120
narrow_position = "bottom"
show_by_default = true
```

In your own config, you only need to set the keys you want to change.

After making a change, restart mddog to see it since mddog reads the config only at startup.

## `theme`

This value sets the page's colors and fonts.

The value can be one theme, which mddog always uses:

```toml
theme = "github-dark"
```

Or it can be a `light` and `dark` pair:

```toml
theme = "light:obsidian-light,dark:obsidian-dark"
```

With a pair, mddog follows the [macOS appearance](https://support.apple.com/en-bh/guide/mac-help/mchl52e1c2d2/mac): light mode automatically uses the `light` theme, and dark mode the `dark` theme.

On Linux, mddog follows the terminal's light or dark mode instead. The Claude Code plugin follows the desktop's setting.

A theme is a built-in name or a path to a custom theme file.

- Built-in themes include `github-light`, `github-dark`, `obsidian-light`, and `obsidian-dark`
- A theme file is any value that ends in `.css` or has a `/` in it. A relative path starts from the config folder, and `~/` is your home folder

`T` in mddog [switches themes](/docs/themes#switch-themes) and saves the one you pick here.

See [Themes](/docs/themes) for more about themes and how to make your own.

## `copy_on_select`

In the viewer, you can select text by dragging it with the mouse or double-clicking to select a word.

By default, `copy_on_select` is set to `false`: selecting text only highlights it, and `Cmd-c` copies it (`Super-c` on Linux).

When set to `true`, mddog automatically copies to clipboard the text you select. `Cmd-c` might not always work in certain terminals (such as iTerm2), so this option is a good workaround.

## `callouts`

This value sets how mddog reads a quote that starts with `[!kind]`.

The default, `"github"`, shows what github.com shows: GitHub's five [alerts](https://github.blog/changelog/2023-12-14-new-markdown-extension-alerts-provide-distinctive-styling-for-significant-content/), and a plain quote for anything else.

Set it to `"obsidian"` to read callouts as [Obsidian](https://help.obsidian.md/callouts) does, with titles, aliases, fold markers and nesting:

```md
> [!faq]- A folded callout with a title
> Click the title to open it.
```

## `open_command`

The command that opens web and mail links, from a click or a [link label](/docs/keys#links-and-buttons). mddog adds the link as the last argument. To put it somewhere else, write `{url}` where it goes.

The default, `["open"]` on macOS or `["xdg-open"]` on Linux, opens the link on the machine where mddog runs. When you use mddog on another machine, such as over SSH or a remote terminal session, that machine isn't the one in front of you. Set a command that sends the link back to the machine you sit at:

```toml
open_command = ["sh", "-c", "printf '%s\\n' \"$0\" | ssh my-laptop 'read -r u && open \"$u\"'", "{url}"]
```

That needs SSH from the remote machine back to yours. If the command fails within 30 seconds, the status row shows the last line of its error output. If the command isn't installed, mddog copies the link instead. If your command runs an app on this machine and waits for it, add `2>/dev/null` to it, so the app's log doesn't collect in mddog's temp file.

The link comes from the file you're reading, so treat it as untrusted. Never pass it to `ssh` as an argument, as in `["ssh", "my-laptop", "open"]`: `ssh` joins its arguments into a shell command on the other machine, so a link with `;` or `$(...)` in it would run commands there. The command above sends the link as input instead.

## `max_width`

This value caps the page's width, in terminal cells. The default is `100`.

In a window wider than that, mddog centers the page with equal margins on the left and right.

```toml
max_width = 120
```

The value must be 20 or more. To turn the cap off, set a value wider than any window, such as `10000`.

## File list extensions

`file_list.extensions` sets which files the [file list](/docs/file-list) shows and which relative links open in mddog. It replaces the default list, so keep `md` and `markdown` when you add one:

```toml title="~/.config/mddog/config.toml"
[file_list]
extensions = ["md", "markdown", "qmd"]
```

## File list preview

The `[file_list.preview]` table sets where the [file list](/docs/file-list) shows the top of the selected file, and how big it is.

| Key | Default | Description |
|---|---|---|
| `position` | `"right"` | Where the preview lives: `"right"`, `"left"`, `"top"`, or `"bottom"` of the list |
| `size` | `"50%"` | Cells (like `80`), or a percentage of the width (or height, when above or below) |
| `narrow_position` | `"bottom"` | Where the preview goes in a narrow window: a position, or `"hidden"` |
| `narrow_columns` | `120` | A window narrower than this many columns is considered narrow |
| `narrow_size` | same as `size` | The preview's size in a narrow window |
| `show_by_default` | `true` | `false` starts with the preview hidden |

For example, to keep the preview below the file list, 15 rows tall:

```toml title="~/.config/mddog/config.toml"
[file_list.preview]
position = "bottom"
size = 15
narrow_position = "bottom"
```

The file list always keeps at least 40 columns beside the preview, or 10 rows above or below it. A preview that would get fewer than 30 columns, or 8 rows, is hidden.

## Font smoothing

mddog automatically applies font smoothing if your macOS system does. On Linux, it always does. This makes text look better on some displays, but it can make it blurry on others.

To turn font smoothing off for macOS and mddog, run this and then restart mddog:

```sh
defaults write -g AppleFontSmoothing -int 0
```

To turn it back on:

```sh
defaults delete -g AppleFontSmoothing
```
